The most important systemic conclusion is that the public configuration and request
model promise policies—geo targeting, cache disablement, memory disablement, cost
limits, capability support—but the router treats several of them as descriptive data
rather than enforceable contracts. That makes successful responses less trustworthy
than outright failures: a call can return `success=True` while violating the requested
country, screenshot, premium, cache, or cost semantics.

## 1. Architecture map

### Entry surfaces

| Surface | Entry point | Construction and request handoff |
|---|---|---|
| CLI | `sgw` and `scrape-gateway` both resolve to the Typer app (`pyproject.toml:35-38`) | Commands call `_build_gateway()`, which constructs `ScrapeGateway.from_config()` and may set a preferred strategy provider (`src/scrape_gateway/cli.py:42-46`). |
| Standalone HTTP | `sgw serve` | Defaults to `0.0.0.0:8100`, accepts an optional token, creates the FastAPI app, and runs Uvicorn (`src/scrape_gateway/cli.py:49-75`). |
| Combined console/REST/MCP | `python -m scrape_gateway.mcp_server` / `sgw-mcp` | A Starlette app mounts console routes, `/v1`, and the FastMCP app; the gateway is a lazy process-global singleton (`src/scrape_gateway/mcp_server.py:101-160`). |
| Python | `ScrapeGateway.from_config()` and `gateway.scrape(ScrapeRequest(...))` | The dataclass request is passed by reference and is mutated during normalization, recipe application, header generation, timeout selection, and run-ID assignment (`src/scrape_gateway/models.py:24-41`; `src/scrape_gateway/router.py:413-455`). |

### Request lifecycle

```text
CLI / HTTP / MCP / Python
        |
        v
load config + discover entry-point/local providers
        |
        v
normalize URL -> apply domain recipe -> synthesize request headers
        |
        v
assign run_id -> optional cache read
        |
        v
order providers:
request preference > recipe > strategy provider > memory > cost rank
        |
        v
for each provider:
capability check -> memory skip check -> adapter call
        |
        +--> adapter failure -> telemetry artifact/memory failure -> next provider
        |
        +--> nominal success -> deterministic content validation
                         |
                         +--> reject -> memory block -> next provider
                         |
                         +--> accept -> Markdown transform -> optional AI audit
                                      -> cache write -> memory/history write
                                      -> telemetry artifacts/report -> return
        |
        v
all failed -> optional AI audit -> telemetry report -> last failure
```

Verified details:

1. Config construction discovers provider classes, instantiates configured providers,
   and appends all unmentioned discoveries (`src/scrape_gateway/router.py:157-178`).
   `from_config()` constructs cache, memory, telemetry, evaluator, timeout, and recipe
   state (`src/scrape_gateway/router.py:271-297`).
2. Recipes are selected by most-specific hostname match and mutate the request before
   cache lookup; only the first route's settings become request defaults, as documented
   (`src/scrape_gateway/recipes.py:75-107`, `145-152`;
   `recipes/README.md:30-37`).
3. Cache lookup happens before routing and is keyed by URL plus `render_js`
   (`src/scrape_gateway/router.py:459-496`; `src/scrape_gateway/cache.py:21-34`).
4. Provider order is cost rank unless request metadata, recipe order, configured
   strategy provider, or learned memory changes it (`src/scrape_gateway/router.py:833-881`).
   A learned provider removes every cheaper provider from the current ladder
   (`src/scrape_gateway/router.py:866-878`).
5. `can_handle()` rejects only unsupported JS, premium, and screenshot requests;
   provider calls are awaited directly (`src/scrape_gateway/provider.py:14-21`;
   `src/scrape_gateway/router.py:511-559`).
6. Successful HTML is deterministically validated, rejected content falls through,
   and accepted HTML is converted to Markdown if the adapter did not supply it
   (`src/scrape_gateway/router.py:602-665`; `src/scrape_gateway/validators.py:78-147`).
7. Evaluation is advisory: exceptions become failed audit outcomes and cannot change
   scrape success (`src/scrape_gateway/router.py:299-383`;
   `src/scrape_gateway/evaluation.py:435-550`).
8. A successful provider result is cached, written to domain memory/history, and then
   persisted as run telemetry (`src/scrape_gateway/router.py:666-739`). All-failed
   requests also produce an audit and report (`src/scrape_gateway/router.py:784-831`).

### Persistent and process state

| State | Default location / lifetime | Actual role |
|---|---|---|
| Artifact cache | `.scrape-gateway/artifacts/<24-char-key>/` | Separate HTML, Markdown, screenshot, and metadata files (`src/scrape_gateway/cache.py:25-34`, `106-126`). |
| Domain memory and extraction patterns | `.scrape-gateway/memory.sqlite` | Domain/provider counters, preferred route/tier, permanent skip decisions, page history, and learned selectors (`src/scrape_gateway/memory.py:11-67`, `143-214`). |
| Run telemetry | `.scrape-gateway/runs/<run-id>/` | Report, attempts, final artifacts, failed artifacts, and evaluator evidence (`src/scrape_gateway/telemetry.py:569-739`). |
| Evaluator cache | `.scrape-gateway/evaluations/` | Content/context-addressed OpenRouter judgment cache (`src/scrape_gateway/evaluation.py:402-433`, `529-550`). |
| Event log | `.scrape-gateway/scrape.log` | Rotating JSONL-like event log initialized on first event, independently of telemetry enablement (`src/scrape_gateway/router.py:28-47`). |
| Console settings | config-adjacent `.scrape-gateway/operator-settings.yml` | Atomically overlays provider enablement and timeouts (`src/scrape_gateway/config.py:139-162`, `165-208`). |
| Active console runs | in-process dictionaries/tasks | Tracks only the current worker process; a scrape task is shielded from client cancellation (`src/scrape_gateway/web.py:891-945`). |
| MCP gateway | process-global singleton | Rebuilt after console settings changes (`src/scrape_gateway/mcp_server.py:104-125`). |

### Extension seams

- Provider packages register under `scrape_gateway.providers`; command packages register
  under `scrape_gateway.commands` (`src/scrape_gateway/discovery.py:68-80`, `128-149`).
- Local provider and command Python files are executed from
  `~/.config/scrape-gateway/providers/` and `commands/`; local providers override an
  entry-point provider with the same `name` (`src/scrape_gateway/discovery.py:83-125`,
  `152-194`).
- `install_requires` can prompt and run `uv pip install` during discovery; its import
  check assumes distribution names map to import names by replacing `-` with `_`
  (`src/scrape_gateway/discovery.py:16-65`).
- Domain recipes are a separate routing/validation extension surface, while `sgw recipe`
  is a CLI workflow replay surface; the two should not be conflated
  (`src/scrape_gateway/recipes.py:35-152`; `src/scrape_gateway/cli.py:1691-1777`).
- The curated registry mixes provider and command packages with `available`/`planned`
  publication status (`registry.yml:5-25`, `27-155`).

## 3. Design weaknesses

### Provider interface consistency across the 15 built-ins

The base contract has only four meaningful elements: `name`, `cost_rank`,
`capabilities`, and `scrape(request)`. It has no structured declaration of supported
request fields, credential readiness, deadline ownership, retry ownership, actual cost,
final URL, or whether output is HTML versus Markdown (`src/scrape_gateway/provider.py:8-25`;
`src/scrape_gateway/models.py:24-64`). The result is adapter-by-adapter semantics:

| Provider | Timeout/error behavior | Request features actually mapped | Output/cost caveat |
|---|---|---|---|
| raw_http | httpx timeout; catches errors; proxy then full-budget direct retry (`src/scrape_gateway/providers/raw_http.py:18-67`) | Headers and proxy only | No cost units; redirected final URL discarded. |
| wreq | Client timeout; catches all; proxy then full-budget direct retry (`src/scrape_gateway/providers/wreq_http.py:18-83`) | Headers and proxy only | No cost units; redirect destination discarded. |
| curl_cffi | Per-request timeout; catches all; proxy then full-budget direct retry (`src/scrape_gateway/providers/curl_cffi_http.py:17-73`) | Headers and proxy only | No cost units; redirect destination discarded. |
| Jina Reader | httpx timeout and catches (`src/scrape_gateway/providers/jina_reader.py:39-72`) | Render engine and selector; ignores gateway headers/mobile/geo | Markdown is duplicated into HTML; hard-coded zero cost (`src/scrape_gateway/providers/jina_reader.py:26-56`). |
| Crawl4AI | Gateway timeout plus ten-second transport margin; catches (`src/scrape_gateway/providers/crawl4ai.py:50-95`, `112-158`) | Broadest mapping: safe headers, render, wait, mobile, delay, ad block, screenshot | No explicit cost ledger. |

The mismatch is not merely uneven feature coverage. `capabilities` is used as an
eligibility guarantee, so a false declaration converts an unsupported request into a
successful-looking contract violation (H-01, H-13, H-14).

### Leaky abstractions

- Adapters decide timeout margins, proxy retry, tier retry, error classification,
  final URL retention, output representation, and cost. The router cannot reason about
  a uniform attempt budget or exact cumulative spend (`src/scrape_gateway/router.py:511-601`).
- A `ScrapeResult` has one `cost_units` and one `route`, so an adapter with internal
  sub-attempts cannot report the same attempt chain as router-level fallback
  (`src/scrape_gateway/models.py:44-61`).
- Request mutation leaks across layers: recipes, generated headers, timeout selection,
  run IDs, memory tiers, and country inference all edit the caller's object
  (`src/scrape_gateway/router.py:413-455`, `513-516`, `877-878`).
- Output type leaks into validation. The router expects `html`, so Markdown adapters
  stuff Markdown into that field to participate in validation (M-06).
- `metadata` is an untyped control channel for `run_id`, preferred provider, tier,
  evaluator goal, no-cache hints, debug artifacts, recipe state, and output annotations.
  It enables both accidental coupling and C-01 (`src/scrape_gateway/models.py:40-41`;
  `src/scrape_gateway/router.py:433-446`, `836-878`).

### Configuration precedence and surprises

Verified routing precedence is:

```text
request metadata preferred_provider
  > domain recipe provider order
  > strategy.provider
  > learned memory
  > ascending cost_rank
```

This follows `_ordered_providers()` (`src/scrape_gateway/router.py:833-881`) and agrees
with the recipe documentation (`recipes/README.md:30-37`). However:

- `strategy.mode` and `max_cost_per_url` do nothing (H-07).
- Base provider config is not an allowlist; omitted discoveries are enabled (H-11).
- Operator settings override same-named base provider fields and can add providers
  absent from base YAML (`src/scrape_gateway/config.py:173-208`).
- Provider `options` reach the constructor, but `api_key_env` does not (M-01).
- Environment values already in `os.environ` win over dotenv; dotenv discovery is CWD,
  then source-project root—not explicit-config directory (`src/scrape_gateway/config.py:103-123`).
- Recipe settings mutate the request before cache identity, but most of those settings
  are absent from the cache key (H-02).

### Adding provider #16

Entry-point or local-file discovery makes registration easy, but safety is entirely
conventional. Discovery verifies only `issubclass(ProviderAdapter)` and optionally
guesses/imports dependencies (`src/scrape_gateway/discovery.py:16-80`, `83-115`).
There is no conformance gate for:

- every declared capability consuming the corresponding request field;
- deadline/cancellation compliance;
- never raising;
- returning the requested artifact;
- normalized failure reasons;
- final URL propagation;
- exact versus estimated cost;
- header/geo/proxy behavior;
- credential absence as availability rather than domain failure.

The example extension even hard-codes a 30-second timeout instead of using the request
deadline (`examples/extension_example.py:26-58`). A provider #16 can therefore abort the
entire ladder (H-09), lie through capability declarations, poison memory, or evade any
future cost policy. Registration should require a provider manifest and a reusable
contract-test suite, not only a class shape.

## 4. Failure handling and resilience

| Failure mode | Current behavior | Assessment |
|---|---|---|
| Timeout | Most built-ins translate library timeouts, but the router has no outer deadline; total request time is the sum of provider budgets and internal retries (`src/scrape_gateway/router.py:511-560`). | Not a request-level budget. Custom extensions can hang; raw proxy fallback can double a provider budget (H-09, M-08). |
| 429 | Classified as `HTTP_429`, then the router records failure and moves on (`src/scrape_gateway/errors.py:6-15`; `src/scrape_gateway/router.py:740-779`). | No Retry-After/backoff; can escalate cost unnecessarily (M-09). |
| 5xx | Same generic fallthrough as other non-proxy failures (`src/scrape_gateway/router.py:740-779`). | No same-provider retry even though test prose says 5xx is worth one (`tests/conftest.py:91-94`). |
| Partial HTML | Length and static substring checks run over raw markup (`src/scrape_gateway/validators.py:78-122`). | Script/style/markup can satisfy minimum length; unknown loading shells pass (validator false negative). |
| Bot page returning 200 | Known strings catch common Cloudflare, CAPTCHA, JS, login, consent, and generic states (`src/scrape_gateway/validators.py:6-53`, `103-122`). | Useful defense but signature-only and truncated at 100k; provider-specific or novel challenges pass. Recipe required/forbidden phrases are the strong per-domain escape hatch (`src/scrape_gateway/recipes.py:57-73`). |
| Missing credentials | Most paid adapters return a normal failed result, often without `failure_reason`; the router records a domain failure (`src/scrape_gateway/providers/scrape_do.py:21-24`; `src/scrape_gateway/router.py:740-779`). | Availability/config failures contaminate target-domain learning (H-06). Providers should be disabled before routing or classified non-domain. |
| Concurrent cache writers | No file lock, staging directory, generation ID, or atomic directory swap (`src/scrape_gateway/cache.py:59-126`). | HTML/Markdown/screenshot/meta can mix (H-03). |
| Cost/retry bound | The provider list is finite, but configured max cost is unused and each adapter may hide internal calls (`src/scrape_gateway/config.py:37-42`; `src/scrape_gateway/providers/scrapedrive.py:51-71`). | Operationally uncapped by the advertised policy; arbitrary extensions expand the ladder. |
| Proxy error | Free HTTP adapters retry directly; if direct still classifies proxy error, the router stops all fallback (`src/scrape_gateway/providers/raw_http.py:18-27`; `src/scrape_gateway/router.py:780-782`). | The direct retry is sensible, but the budget is doubled and a provider-specific proxy error can suppress unrelated providers. |
| Memory poisoning | Failures/blocks are domain/provider aggregates, with no request-profile key, expiry, or recovery probe (`src/scrape_gateway/memory.py:111-190`). | Persistent false routing decisions are likely after config changes or mixed workloads (H-06). |
| Evaluation failure | Evaluator exceptions and artifact errors are contained and recorded (`src/scrape_gateway/router.py:333-355`). | Good isolation; it is correctly advisory. Its API cost is separate from—and not covered by—the dead scrape cost ceiling. |
| Client disconnect | Console calls are shielded and continue to completion (`src/scrape_gateway/web.py:928-945`). | Good for evidence persistence, but active state is per process; multi-worker visibility is incomplete. |

The fallback order is reasonable for a single homogeneous request—cheap providers first,
validation, then escalation—but memory's behavior is too aggressive. Once memory selects
a provider, every cheaper provider is removed instead of merely moving the winner first
(`src/scrape_gateway/router.py:866-878`). That optimizes repeat latency at the cost of
recovery, cost regression detection, and changed site behavior. It also carries a
ScrapeDrive tier learned under a different request profile.

## 6. Drift, cruft, and contradictions

### Documentation and release drift

1. The README badge says 0.16.0 while package and changelog are 0.17.4
   (`README.md:3-5`; `pyproject.toml:1-4`; `CHANGELOG.md:8-12`).
2. Python API docs claim a 30-second request default; the dataclass and gateway default
   are 45 seconds (`docs/python-api.md:24-36`; `src/scrape_gateway/models.py:24-41`;
   `src/scrape_gateway/config.py:69-75`).
3. `docs/extensions.md` and `registry.yml` still call `sg-sitemap` a Trafilatura
   extension (`docs/extensions.md:88-100`; `registry.yml:13-18`), while the
   implementation uses `ElementTree` and the changelog explicitly says Trafilatura was
   removed (`extensions/sg-sitemap/src/sg_sitemap/__init__.py:1-7`, `42-74`;
   `CHANGELOG.md:223-228`).
4. Provider docs call ScrapeDrive's endpoint configurable through
   `SCRAPEDRIVE_BASE_URL`, but the adapter ignores it (M-07).
5. `sg-sitemap` and `sg-cache` are marked `planned` in the registry even though source
   docs present them as included and the Docker image installs both
   (`registry.yml:13-25`; `Dockerfile:9-13`; `docs/extensions.md:88-113`).
6. Architecture docs say there are “190+ unit tests,” while the test tree also includes
   credential-triggered live integration files and CI special-cases them
   (`docs/architecture.md:62-80`; `.github/workflows/ci.yml:21`).
7. The example config advertises `max_cost_per_url` even though it is inert
   (`scrape-gateway.example.yml:32-35`; H-07), and comments `api_key_env` despite that
   field being inert (lines 19-21; M-01).

### Dead, duplicate, or misleading configuration

- Dead: `CacheConfig.enabled`, `StrategyConfig.mode`, `StrategyConfig.max_cost_per_url`,
  `ProviderConfig.api_key_env`, and `SCRAPEDRIVE_BASE_URL`.
- Ambiguous: `use_cache` is a read flag, not a full cache policy; `use_memory` is only
  partially observed.
- Duplicate state: new `domain_provider_stats` and legacy `domain_routes` are both
  updated on every success, but routing reads only the new table
  (`src/scrape_gateway/memory.py:21-67`, `73-109`, `143-158`).
- Two recipe concepts share a name: domain recipes alter routing; CLI recipe files
  orchestrate URL lists/extraction. The docs distinguish them only by location, which
  invites operator confusion (`docs/configuration.md:69-94`;
  `src/scrape_gateway/cli.py:1691-1777`).
- Discovery can mutate the Python environment during what appears to be provider
  enumeration (`src/scrape_gateway/discovery.py:16-65`), and dependency-name guessing is
  not reliable for packages whose import differs from their distribution name.

### Packaging and operational drift

- `uv.lock` exists locally but is ignored, while Docker installs open dependency ranges;
  image builds are not reproducible (`.gitignore:15`; `Dockerfile:5-13`;
  `pyproject.toml:9-33`).
- The Docker image installs Doppler through a live apt repository during build, adding a
  large unrelated availability/supply-chain dependency to the scrape runtime
  (`Dockerfile:15-20`).
- Compose publishes port 8100 and does not require `SGW_MCP_TOKEN`
  (`docker-compose.yml:5-14`; `.env.example:32-37`), compounding H-12.
- The root contains 16 ignored PNG investigation/screenshots plus local `scrape-gateway.yml`,
  `uv.lock`, runtime/output directories, and browser tooling state. The ignore rules hide
  these from ordinary `git status` (`.gitignore:15-21`). They are not release inputs and
  should live under an explicit local-artifacts directory or outside the checkout.

## 7. Top 10 recommendations

Ordered by expected risk reduction, then effort.

| Rank | Recommendation | Impact | Effort | Regression risk |
|---:|---|---|---|---|
| 1 | **Close both containment holes immediately.** Treat run IDs and cache keys as opaque IDs matching strict regexes, reject absolute/`..` values, resolve paths, require `resolved.is_relative_to(root.resolve())`, and test that no outside path is touched. | Critical | Small | Low; only unsafe/undocumented IDs break. |
| 2 | **Define a canonical request profile and make cache commits atomic.** Hash URL plus every response-shaping option (country, render, premium, mobile, headers/referer, waits, ad blocking, artifact type, recipe identity); write a complete generation to a temp directory and atomically swap or use a manifest/version under a per-key lock. | Very high | Large | High; cache keys invalidate and concurrency/storage behavior changes. |
| 3 | **Turn flags/config into executable policy.** Honor `cache.enabled`; define separate read/write cache controls; make `use_memory=False` bypass all reads/writes; validate strategy modes; enforce `max_cost_per_url` before each attempt. Reject unknown/dead config instead of silently accepting it. | Very high | Medium | Medium; callers relying on accidental behavior will change. |
| 4 | **Strengthen the provider contract before provider #16.** Add structured `supported_options`, readiness/credential validation, output type, exact/estimated cost semantics, and final URL. Enforce country and all declared capabilities, and run one reusable conformance suite against every built-in and extension. | Very high | Large | Medium-high; false capability declarations will be exposed. |
| 5 | **Put every provider attempt behind a router-owned deadline and exception boundary.** Catch exceptions, cancel where possible, record a normalized failure, and continue. Add explicit retry policy for 429/Retry-After and selected 5xx with one total request deadline, not per-leg reset budgets. | High | Medium | Medium; timing and fallback ordering change. |
| 6 | **Redesign memory around request profile and recovery.** Key statistics by domain plus material capability/profile, classify config/credential failures as non-domain, add decay/TTL and half-open probes, and stop removing all cheaper providers merely because one once worked. Provide reset/inspection APIs. | High | Large | High; learned routing and SQLite migration change. |
| 7 | **Introduce an attempt/cost ledger.** Record every router attempt and adapter sub-attempt with exact or explicitly estimated units, including ScrapeDrive tiers and optional evaluator cost. Derive result, batch, telemetry, and budget totals from the ledger. | High | Medium | Medium; telemetry schema and displayed totals change. |
| 8 | **Make service exposure safe by default.** Bind standalone service to loopback unless explicitly overridden, require a token for non-loopback bind, and implement DNS/IP checks that block loopback, link-local, private, and cloud-metadata targets unless explicitly allowlisted. Apply the same policy to redirects. | High | Medium | Medium-high for users intentionally scraping intranet targets; support an explicit allowlist. |
| 9 | **Remove shared mutation and propagate final URLs.** Copy requests/metadata per scrape, generate a fresh run ID unconditionally unless a validated internal override is used, preserve `requested_url` and `final_url`, and resolve links/metadata against the latter. | High | Small-medium | Low-medium; fixes batch telemetry and redirect behavior. |
| 10 | **Make packaging/tests/docs prove the shipped contract.** Split live tests by marker, add Python 3.13/image and wheel-install tests, verify every MCP tool from the `mcp` extra, add concurrency/path/cost tests, generate version/default/provider tables from code, and reconcile registry publication state. | High | Medium | Low; mostly test/release work, though packaging dependencies may grow. |

### Suggested sequencing

1. Ship recommendation 1 as a security hotfix.
2. Add failing tests for H-01 through H-10 before changing semantics.
3. Implement recommendations 3, 5, and 9 as small, reviewable policy changes.
4. Design the request profile, provider manifest, attempt ledger, and memory migration
   together; they share identity and cost semantics.
5. Finish with deployment defaults and doc/package regeneration, then validate the real
   CLI, REST, MCP, and browser-console paths rather than stopping at unit tests.

The codebase has useful pieces—cheap-first routing, deterministic validation, recipes,
advisory evaluation isolation, extension discovery, and rich evidence persistence—but
the next release should prioritize truthful contracts over adding another provider.
Until geo, caching, memory, cost, artifact, and timeout promises are centrally enforced,
more adapters increase the number of ways a successful response can be wrong.
